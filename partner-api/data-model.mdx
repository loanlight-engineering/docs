The request schemas for the Partner API are NestJS DTOs in `partner-api/dto/`, validated with `class-validator`. This page is the field-level reference; the endpoint pages ([Loans](/partner-api/loans), [Audits](/partner-api/audits)) describe behaviour.

## CreatePartnerLoanDto

Body of [`POST /api/v1/partner/loans`](/partner-api/loans). File: `create-partner-loan.dto.ts`.

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `loanNumber` | string | yes | `@IsString @MaxLength(100) @Sanitize(100)` |
| `mismoXml` | string (base64) | yes | `@IsString @IsSafeBase64()` (Buffer round-trip — stack-safe for multi-MB payloads) |
| `documents` | `DocumentDto[]` | no (default `[]`) | `@IsArray @ValidateNested({each}) @Type(DocumentDto)` |
| `metadata` | `LoanMetadataDto` | no | `@ValidateNested @Type(LoanMetadataDto)` |
| `skipClassification` | boolean | no (default `false`) | `@IsBoolean`. Docs are still registered and uploaded; only classification is skipped. |

### DocumentDto

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `fileName` | string | yes | `@MaxLength(255) @Sanitize` |
| `content` | string (base64) | yes | `@IsSafeBase64()` |
| `mimeType` | string | **yes** | `@IsString() @MaxLength(100) @Sanitize(100)` — no `@IsOptional()`, so omitting it (or sending a value `@Sanitize` wipes) fails validation with `400` |
| `documentType` | string | no | `@MaxLength(100)`; captured but informational |

### LoanMetadataDto

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `estimatedClosingDate` | string | no | `@IsDateString` (YYYY-MM-DD) |
| `lenderCode` | string | no | ≤ 100 chars |
| `loanType` | string | no | ≤ 100 chars (see note) |
| `loanProgramName` | string | no | ≤ 255 chars |
| `bankStatementIncome` | `BankStatementIncomeMetadataDto` | no | Nested object carrying all bank-statement income context. Supersedes any top-level income fields an older integration may send when present. See below. |

<Note>
The flat top-level fields `borrowerType` and `incomeQualification` are **de-documented as of LOA-2096** — they no longer appear in the published OpenAPI document or Redoc. They remain accepted (with their original validation) so integrations built against the old shape keep working, but `bankStatementIncome` is the documented and forward path. The nested object wins whenever both are present.
</Note>

### BankStatementIncomeMetadataDto

`LoanMetadataDto.bankStatementIncome` — the only documented way to send bank-statement income context. File: `create-partner-loan.dto.ts`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `basis` | `"personal" \| "business"` | no | Borrower type for income qualification. Explicit only — not derivable from other metadata. Absent leaves the income-context skip decision indeterminate. |
| `months` | `12 \| 24` | no | Explicit averaging window in months. Overrides the value derived from the resolved loan program (precedence: override > derived > skip). |
| `expenseFactor` | string | no | Business-only expense haircut, 0–1 decimal with **at most 4 decimal places** (e.g. `"0.1500"`). Applied as `qualified = deposits × ownershipPercentage × (1 − expenseFactor)`. Ignored unless the effective basis is `"business"`. String-typed deliberately — a JSON number is coerced to a string, but the 4-decimal cap is enforced either way to prevent silent rounding into the `numeric(5,4)` column. |
| `ownershipPercentage` | string | no | Business-only ownership share, 0–1 decimal with at most 4 decimal places (e.g. `"1.0000"`; 1 = 100%). Omitted or absent means 100% ownership. Same typing rationale as `expenseFactor`. |

**Example:**
```json
{
  "bankStatementIncome": {
    "basis": "business",
    "months": 12,
    "expenseFactor": "0.3500",
    "ownershipPercentage": "1.0000"
  }
}
```

**Persisted columns (migration `0300`):** `loans.expense_factor` / `loans.ownership_percentage` (nullable `numeric(5,4)` — `NULL` means the partner never supplied a value, which is the provenance signal). `borrower_files.expense_factor_source` / `borrower_files.ownership_percentage_source` track which component supplied the value in use (`'partner' | 'default' | 'viewer_edit'`).

<Warning>
**`loanType` is free-form text (the `LoanTypeSchema` mirrors this).** The DB column is `text`; the value passes through verbatim (`loan.service.ts::resolveLoanType`). There is **no** `@IsEnum` and **no** `@Matches` regex.

This is enforced by design (LOA-1088). The `partner-loans.controller.spec.ts` test group `"LoanTypeSchema (OpenAPI response schema — LOA-1088 contract parity)"` asserts the response schema has no `enum` key, no `pattern` key, `type: "string"`, `maxLength: 100`, and `nullable: true`. Re-adding `enum: Object.values(LoanType)` or a slug regex like `^[A-Za-z0-9_-]+$` re-introduces the contract lie and rejects valid values such as `bank_statement_12mo` or aliased labels like `"Bank Statement - 12 Month"`.

`@Sanitize(100)` runs **before** `@MaxLength(100)` (it truncates to 100 first; non-string inputs are wiped to `undefined` so `@IsOptional` short-circuits). The max lengths differ intentionally: `loanType = 100`, `loanProgramName = 255`.
</Warning>

## CreatePartnerAuditDto

Body of [`POST /api/v1/partner/audits`](/partner-api/audits). File: `create-partner-audit.dto.ts`.

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `loanId` | string (uuid) | yes | `@IsUUID()` |
| `agents` | string[] | no | `@IsArray @IsString({each})`. Omitted or empty → all entitled standard agents run (see note). |
| `options` | `AuditOptionsDto` | no | `@ValidateNested @Type` |

Example `agents` values: `piiValidation`, `documentHealth`, `urlaExtraction`, `propertyData`, `redFlags`, `creditEvaluation`, `bankStatementIncome`.

<Note>
`bankStatementIncome` is **opt-in only**: it runs when explicitly named in `agents[]` **and** the lender holds an explicit entitlement row. It is never included when `agents[]` is omitted, regardless of entitlement. A non-empty `agents[]` runs only the named agents plus their required upstream inputs.
</Note>

### AuditOptionsDto

| Field | Type | Required | Validation |
| --- | --- | --- | --- |
| `estimatedClosingDate` | string | no | `@IsDateString` (YYYY-MM-DD) — overrides the loan's stored closing dates |

## ResultsAccessUrlResponseDto

Response of [`POST /api/v1/partner/audits/:auditId/results/access-url`](/partner-api/results-and-access-urls). File: `results-access-url.dto.ts`.

```ts
{

}
```

## Response schemas

The full response shapes are documented on the endpoint pages, since several differ from their Swagger schemas:

- Loan create / detail / status / list, document upload and listing — [Loans API](/partner-api/loans).
- Audit create / status / errors / classifications — [Audits API](/partner-api/audits).
- Audit results (`agents`, `creditEvaluations`, `summary`) and access URLs — [Results and access URLs](/partner-api/results-and-access-urls).

<Note>
**Two known schema/reality gaps to keep in mind:** `GET /loans` returns raw snake_case `LoanRecord` rows (not the camelCase Swagger schema), and document statuses in create/upload responses are `new | updated | existing` (not the Swagger example's `"uploaded"`, which only appears in detail/pipeline responses).
</Note>
