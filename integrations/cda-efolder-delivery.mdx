The CDA eFolder delivery system delivers completed collateral data audit (CDA) PDFs from `loanlight-api` into Encompass eFolders. It is split across two services: `loanlight-api` owns the **producer** (PDF identity, lender eligibility, publication outbox, and EventBridge emission), and `loanlight-integrations` owns the **consumer** (eFolder credentials, destination selection, provider delivery, and the consumer ledger).

<Warning>
**No lender is currently enabled.** No `cda_efolder_delivery_config` row is seeded. Do not enable a lender on either side until an approved provider adapter passes the provider contract suite and the per-lender preflight below is complete.
</Warning>

## How it works

When a `collateral_review_orders` row of type `cda` reaches `status = 'succeeded'` and the lender's `cda_efolder_delivery_enabled` flag is on, the order becomes **eligible**: the producer sets `cda_efolder_eligible_at` and binds the Encompass loan GUID and the PDF's SHA-256 to the order. A background sweep picks up eligible orders and publishes one EventBridge event per order to the default bus. `cda_efolder_event_published_at` is set only after EventBridge acknowledges the event — it does not mean the eFolder delivery completed.

The integrations consumer subscribes to that event type and handles eFolder credentials, destination selection, and actual delivery.

## Feature flag

`cda_efolder_delivery_enabled` is a per-lender `lender_feature_flags` row. Set it to `false` to pause new claims and new republishes. A disable is checked atomically at claim time; it does not cancel an already-acquired lease or retract an event that EventBridge has already accepted.

Keep every lender absent/off until the cross-service preflight below is complete. Set it to `true` to resume; the flag write releases only eligible rows that are unleased, already due, or carry a retry error.

<Warning>
**The only supported activation path is the authenticated internal-super-admin portal/API feature-flag route:** `PUT /api/v1/portal/lenders/:id/feature-flags`. Direct SQL (`enabled = true`) is not sufficient. The sweep checks the flag with `cdaEfolderDeliveryEnabledSql`, which validates that the flag row was written by a `super_admin` on an internal lender (or with no lender, which covers WorkOS offboarding) on behalf of an active, non-internal lender. A row written outside this path does not satisfy those conditions and is treated as absent.
</Warning>

<Note>
**eFolder delivery persists after admin offboarding (LOA-3075).** The predicate deliberately does not check the enabling admin's active status. Deleting, deactivating, or offboarding the `super_admin` who turned on delivery (which WorkOS handles by setting their `lender_id` to null) no longer switches delivery off mid-flight. Only an explicit `enabled = false` write disables delivery.
</Note>

## AVM report acquisition columns on `collateral_review_orders`

Migration `0107` (LOA-2921) adds AVM-specific producer columns to `collateral_review_orders`. AVM delivery is a two-phase flow: first the AVM PDF is fetched from the vendor, then it is published to EventBridge for eFolder delivery. The columns mirror the CDA pattern but carry the `avm_` prefix.

**AVM report acquisition phase** (fetch the PDF from Clear Capital):

| Column | Type | Notes |
|---|---|---|
| `avm_report_acquisition_eligible_at` | `timestamptz` | Set when the AVM order is eligible for PDF fetch. NULL when ineligible. Only valid on `order_type = 'avm'` + `status = 'succeeded'`. |
| `avm_report_fetch_attempt_count` | `integer NOT NULL default 0` | Monotonic fetch attempt counter. CHECK `>= 0`. |
| `avm_report_next_attempt_at` | `timestamptz` | When the next fetch attempt is due. NULL after the PDF is acquired. |
| `avm_report_last_error_code` | `text` | Most recent fetch error. Recognized codes: `missing_vendor_order_id`, `missing_vendor_tenant_id`, `deliverable_not_ready`, `deliverable_ambiguous`, `document_listing_unavailable`, `document_not_found`, `vendor_request_failed`, `empty_pdf`, `invalid_pdf_content_type`, `invalid_pdf_magic`, `pdf_too_large`, `artifact_storage_unavailable`, `artifact_conflict`. |

AVM PDFs are stored in `pdf_s3_key` under the key `collateral-review/{loan_id}/avm-{id}.pdf`. A successful fetch sets `avm_efolder_eligible_at` and `avm_efolder_pdf_sha256`, which triggers the eFolder publication phase.

**AVM eFolder publication phase** (EventBridge outbox, parallel to CDA):

| Column | Type | Notes |
|---|---|---|
| `avm_efolder_eligible_at` | `timestamptz` | Set when the AVM PDF is ready for delivery. Requires `avm_report_acquisition_eligible_at` and a non-null `pdf_s3_key` and `avm_efolder_pdf_sha256`. |
| `avm_efolder_pdf_sha256` | `text` | Lowercase 64-character SHA-256 of the AVM PDF. CHECK `^[0-9a-f]{64}$` when non-null. |
| `avm_efolder_encompass_loan_id` | `text` | Encompass loan GUID. Non-blank when non-null. |
| `avm_efolder_event_attempt_count` | `integer NOT NULL default 0` | Publication attempt counter. CHECK `>= 0`. |
| `avm_efolder_event_next_attempt_at` | `timestamptz` | Next publication attempt due. NULL after successful EventBridge acknowledgement. |
| `avm_efolder_event_published_at` | `timestamptz` | Set when EventBridge acknowledges. Does not mean eFolder delivery completed. |
| `avm_efolder_event_last_error_code` | `text` | Most recent publication error. Same codes as the CDA path (`missing_encompass_loan_id`, `loan_lender_mismatch`, `invalid_encompass_loan_id`, `invalid_pdf_s3_key`, `invalid_pdf_sha256`, `eventbridge_rejected`, `eventbridge_transport_error`). |

Two partial indexes on `collateral_review_orders` back the AVM publication sweep: `collateral_review_orders_avm_acquisition_due_idx` (pending acquisitions) and `collateral_review_orders_avm_efolder_due_idx` (pending publications).

## Producer outbox columns on `collateral_review_orders` (CDA)

Migrations `0073`–`0076` (LOA-2703) add these columns to `collateral_review_orders`:

| Column | Type | Notes |
|---|---|---|
| `cda_efolder_eligible_at` | `timestamptz` | Set when the order becomes eligible for delivery. NULL means the order is inert (pre-feature, or `cda_efolder_delivery_enabled` was off when it succeeded). |
| `cda_efolder_encompass_loan_id` | `text` | The Encompass loan GUID bound at claim time. A row cannot publish without a non-null, nonblank value. |
| `cda_efolder_pdf_sha256` | `text` | Lowercase 64-character SHA-256 of the PDF at the bound S3 key. CHECK `^[0-9a-f]{64}$`. Bound at eligibility time. |
| `cda_efolder_event_attempt_count` | `integer NOT NULL default 0` | Monotonic claim generation counter. A non-zero future `cda_efolder_event_next_attempt_at` with no error code is an active lease. |
| `cda_efolder_event_next_attempt_at` | `timestamptz` | When the next claim attempt is due. NULL after a successful publication. |
| `cda_efolder_event_published_at` | `timestamptz` | Set when EventBridge acknowledges the event. Non-null means the event was sent; it does not mean eFolder delivery completed. |
| `cda_efolder_event_last_error_code` | `text` | The most recent error, or NULL when the last attempt succeeded or no attempt has been made. |

CHECK constraints:
- `collateral_review_orders_efolder_eligibility_check` — `cda_efolder_eligible_at` is non-null only when `order_type = 'cda'`, `status = 'succeeded'`, and both `pdf_s3_key` and `cda_efolder_pdf_sha256` are non-null.
- `collateral_review_orders_efolder_publication_check` — `cda_efolder_event_published_at` is non-null only when `cda_efolder_eligible_at`, `cda_efolder_encompass_loan_id`, and `cda_efolder_event_attempt_count > 0` are all set.
- `collateral_review_orders_efolder_sha256_check` — the SHA-256 matches `^[0-9a-f]{64}$` when non-null.
- `collateral_review_orders_efolder_loan_id_check` — `cda_efolder_encompass_loan_id` is non-blank when non-null.

## The sweep

The advisory-locked sweep runs every five minutes. It picks up eligible, unleased, and due rows, acquires a generation-fenced lease, and publishes to EventBridge. The sweep emits Datadog metrics with the `environment` tag:

- `loanlight.cda_efolder.publication_claim`
- `loanlight.cda_efolder.eventbridge_accepted`
- `loanlight.cda_efolder.publication_retry`
- `loanlight.cda_efolder.expired_claim`
- `loanlight.cda_efolder.retrying_unpublished_count` — per-reason gauge of enabled, eligible, succeeded rows that are actively retrying (inside backoff or with a retry error code). Tagged by `reason` (the error code vocabulary). Emitted at the heartbeat cadence (every five minutes), not per-event.
- `loanlight.cda_efolder.sweep_heartbeat` — emitted twice per tick (once on advisory-lock acquisition, once after the batch). A tick can run for tens of minutes at the batch cap; the leading emit is what keeps the absence monitor alive.

`oldest_eligible_unpublished_age_seconds` measures time since a row became **due** (`COALESCE(next_attempt_at, eligible_at)`), not since it became eligible. A row inside its lease or backoff reads 0.

## Error codes

| Code | Meaning |
|---|---|
| `missing_encompass_loan_id` | No Encompass loan GUID is bound to the order. Reparable — see below. |
| `invalid_encompass_loan_id` | The bound GUID is not in the canonical format the contract requires. Reparable — see below. |
| `loan_lender_mismatch` | The loan's lender changed after the order was written. No repair path. |
| `invalid_pdf_s3_key` | `pdf_s3_key` diverged from the expected key. No repair path. |
| `invalid_pdf_sha256` | The stored SHA-256 does not match the PDF at the bound key. No repair path. |
| `eventbridge_rejected` | EventBridge rejected the publication call. No automatic repair. |
| `eventbridge_transport_error` | Transient network/transport error. Retries with exponential backoff capped at six hours. |

`loan_lender_mismatch`, `invalid_pdf_s3_key`, and `invalid_pdf_sha256` have no remedy inside this repository — they retry every six hours indefinitely while the `cda-efolder-backlog-aged` monitor pages. Escalate to the owning team with the order row.

## Encompass loan ID repair

When an order is parked on `missing_encompass_loan_id` or `invalid_encompass_loan_id`, an internal super-admin repair endpoint can bind or rebind the Encompass loan GUID. The repair:

- Is internal-super-admin-only. Two attestations are required: `provider_ui_verified` and `reviewed_support_case`.
- Refuses to overwrite a GUID the contract already accepts (the existing value is valid — not a repair target).
- Requires an 8–200 character printable-ASCII evidence note. Do not include borrower data, loan terms, tokens, credentials, or document contents.
- Audits both outcomes: `loan.encompass_id_linked` (first link) and `loan.encompass_id_repair_replayed` (replay of an already-correct ID). Both record `rescheduledOrderIds`.
- Wakes only rows parked on `missing_encompass_loan_id` or `invalid_encompass_loan_id`. Rows carrying `loan_lender_mismatch`, `invalid_pdf_s3_key`, `invalid_pdf_sha256`, or `eventbridge_rejected` are not touched.

<Note>
**Known window:** A row being claimed right now has a NULL error code (the claim nulls it; `scheduleRetry` re-sets it). A repair landing in this window matches nothing and audits `rescheduledOrderIds: []`. Re-run the repair — it is idempotent and audited.
</Note>

## Cross-service preflight

Before enabling a lender, verify:
- AWS account and region for the API producer.
- The EventBridge default bus and IAM permission.
- S3 bucket/key access and KMS decrypt access for the recorded PDF.
- The shared event contract release.
- The integrations consumer deployment.

The following are owned by `loanlight-integrations` and are not configurable here: document-push queue routing, per-lender routing-config overrides, delivery claim management, and the `document-push-dlq` redrive.

## Consumer side (loanlight-integrations)

<Warning>
The Developer Connect delivery module (`packages/encompass/src/cda-efolder-delivery/`) was **deleted in phase 1** and the remaining infrastructure was cleaned up in **phase 2** (#619, #610). The old `CdaEfolderDeliveryRule`, its event archive, the target DLQ, and the `cda_efolder_delivery` / `cda_efolder_delivery_config` tables were deleted in phase 2. The idle processing queue and its DLQ remain until the prod application stack stops importing their CloudFormation exports. `DocumentPushRule` is now the only rule that routes AVM and CDA delivery events.
</Warning>

### Route

Both `loanlight.avm.efolder.delivery.requested.v1` and `loanlight.cda.efolder.delivery.requested.v1` events are now handled by **`DocumentPushRule`** (the same EventBridge rule that routes classified documents), which delivers them to the `document-push` SQS queue:

```
loanlight-api ──PutEvents──▶ EventBridge default bus
                                │  DocumentPushRule
                                │  source = loanlight.aus
                                │  detail-type ∈ { loanlight.documents.classified,
                                │                  loanlight.cda.efolder.delivery.requested.v1,
                                │                  loanlight.avm.efolder.delivery.requested.v1 }
                                ▼
               SQS document-push (visibility 900 s, 5 receives)
                                │  └─▶ document-push-dlq after 5 failed receives
                                ▼
     QueueConsumerService.handleDocumentPush
       read detail-type
         ├─ AVM / CDA ──▶ handleReportDelivery
         │                  └─▶ EfolderFileDeliveryService.deliver
         │                        └─▶ DocumentPushService.push
         └─ documents.classified ──▶ existing document-push path
```

Each report message goes through these steps:

1. **Parse** with the shared-types parser for the event kind (`parseAvmEfolderDeliveryRequestedEvent` or `parseCdaEfolderDeliveryRequestedEvent`). A parse failure is logged (`report_delivery.invalid_payload`) and consumed.
2. **Resolve the EPC transaction.** When `auditRunId` is present: `getTransactionRecordOwningStateOrThrow(auditRunId)` finds the record that owns that state even after a re-audit. When `auditRunId` is absent or null: `getTransactionRecordByEncompassLoanIdOrThrow(encompassLoanId)` finds the loan's earliest `transaction_record` with an `active transaction_state` whose status is not `cancelled` or `failed`. No row found by either path → `no_transaction` (message consumed, not retried).
3. **Shadow check.** `transaction_record.is_shadow = true` → `shadow_skipped`.
4. **Verify bytes.** The S3 object is streamed and re-hashed. Hash mismatch → `content_mismatch` (terminal). Object missing or stalled → `retriable` (SQS redelivers, up to 5 receives).
5. **Push** via `DocumentPushService.push` with `documentId = orderId`, `contentHash = pdfSha256`, `classificationType = avm_report | cda_report`, `documentName = filename`.
6. **Open validation.** On the `attached` transition, the push stores the PATCH's `X-Correlation-ID` and starts the validation clock (`validation_pending_since`, migration `041`).

<Note>
`auditRunId` (the EPC correlation id, i.e. `transaction_state.id`) is included in event payloads as of shared-types 2.5.0 (LOA-2921). When present, the consumer resolves the transaction record via `getTransactionRecordOwningStateOrThrow(auditRunId)`, which finds the record that owns that state **even if a re-audit has since superseded it**, then files the report against the record's newest active (non-cancelled, non-failed) state. When `auditRunId` is absent or `null`, the lookup falls back to `getTransactionRecordByEncompassLoanIdOrThrow(encompassLoanId)` (earliest active record, unchanged from the previous behaviour). The `encompassLoanId` field is always used for final loan-id verification regardless of which lookup path resolved the record.
</Note>

### Where the file lands

Migration `040_seed_collateral_report_routing.sql` seeds two entries in `document_push_routing_config`:

| Routing key | Folder (`nameTemplate`) | EPC type (`typeTemplate`) |
|---|---|---|
| `avm_report` | `AVM Report` | `avmReport` |
| `cda_report` | `CDA Report` | `cdaReport` |

A lender that wants a different folder gets a per-lender override row in the same table, edited through the routing-config editor. The file name is not configurable: both keys are `GENERATED_DOCUMENT_CLASSIFICATION_TYPES`, so the resolver ignores any `fileNameTemplate` and uses the event's `filename` field directly.

### Replay safety

Two layers apply (same as any document push):

1. **Content ledger.** `document_push_record` is checked for a prior delivery of the same content (`content_hash = pdfSha256`) to the same folder. A hit in `attached` or `completed` state (unless `validation_status = 'processing_failed'`) returns `already_delivered`.
2. **Delivery claim.** `document_delivery_claim` acquires `(transaction_record_id, sha256:<pdfSha256>, <folder>)` before anything leaves the process.

### Delivery validation

An `attached` record enters open validation (added by migration `041`). Validation closes on:

- **`validated`** — both a `response:updated` listing the `epc_resource_id` and a `response:processed` matching the `epc_correlation_id` are on file and the processed status is success.
- **`processing_failed`** — the `response:processed` event reports failure. The delivery claim is released so a republish re-files.
- **`timed_out`** — no terminal events within 30 minutes of `validation_pending_since`. The claim is kept for dedup.

### DLQ and monitoring

Report messages share the `document-push` queue and `document-push-dlq` with classified-document pushes. The `document-push-dlq-depth` alarm fires on ≥ 1 visible message for two 5-minute periods.

The retired Developer Connect Datadog monitors (`cda-efolder-delivery-consumer-error`, `cda-efolder-delivery-manual-review`, `cda-efolder-delivery-oldest-unfinished-age`, `cda-efolder-delivery-payload-conflict`, `cda-efolder-delivery-processing-dlq-depth`, `cda-efolder-delivery-provider-retry`, `cda-efolder-delivery-sweep-heartbeat-missing`) are marked `deprecated: true` in `monitors.registry.json` — nothing emits `cda_efolder_delivery.*` events any more, so the apply job deletes them. The four `*-dlq-depth` monitors remain live until phase 2 removes the queues.

## Datadog monitors

Six monitors cover the CDA eFolder producer path (`packages/api/observability/datadog/`):

| Monitor | Threshold |
|---|---|
| `cda-efolder-backlog-aged` | Warns at 2 h, alerts at 6 h of oldest unpublished age. |
| `cda-efolder-publication-stuck` | Alerts when a publication claim is in-flight past a deadline. |
| `cda-efolder-sweep-missing` | Alerts after 15 minutes without a sweep heartbeat. |
| `cda-efolder-expired-claim` | Warns at ≥1, alerts at ≥3 expired leases in the last 30 minutes. An expired claim means a lease was acquired but did not finish — a flag enable or operator repair alone is not an expired claim. |
| `cda-efolder-metrics-observation-failed` | Log alert: fires when a backlog observation cycle fails (`cda_efolder.metrics_observation_failed`). While this alert is active, backlog and retry gauges may not be trustworthy — investigate database/query health before relying on them. |
| `cda-efolder-retry-backlog-stuck` | Alerts when any per-reason `retrying_unpublished_count` gauge holds ≥1 for a full 15-minute window. `published_at` means producer acceptance by EventBridge only, not completed eFolder delivery. Use the runbook SQL to find the affected order(s). |

## AVM eFolder Datadog monitors

Nine monitors cover the AVM producer path (`packages/api/observability/datadog/avm-*.json`, added LOA-2921.7). The acquisition phase (fetching the report PDF from Clear Capital) and the publication phase (publishing to EventBridge) each have their own monitor set.

**Acquisition monitors:**

| Monitor | Threshold / Trigger |
|---|---|
| `avm-report-acquisition-stuck` | `loanlight.avm_report.oldest_eligible_unstaged_age_seconds` warns at 2 h, alerts at 6 h. Counts from `avm_report_acquisition_eligible_at`. Rows in backoff and parked terminal rows keep it lit. Run the acquisition-due query; classify each row as lease, backoff, or parked. A parked terminal row re-notifies every 30 min until resolved; mute the whole monitor with an expiry and a named note, then re-run the query — a second stuck row cannot page while muted. |
| `avm-report-terminal` | Fires on any `avm_report.acquisition_terminal` log, whatever the reason. Only terminal codes emit this event. Follow the terminal acquisition runbook for the logged reason. |
| `avm-report-sweep-missing` | No acquisition heartbeat for 15 minutes. The sweep is the only recovery for a missed webhook or a deliverable not yet ready, so unstaged reports accumulate. Check scheduler and task health, then the acquisition advisory lock holder, before touching any row. |

**Publication monitors:**

| Monitor | Threshold / Trigger |
|---|---|
| `avm-efolder-backlog-aged` | `loanlight.avm_efolder.oldest_eligible_unpublished_age_seconds` warns at 2 h, alerts at 6 h. Counts from `COALESCE(avm_efolder_event_next_attempt_at, avm_efolder_eligible_at)` for validly enabled lenders only. Leased and backed-off rows read 0. Run the publication query. |
| `avm-efolder-retry-backlog-stuck` | `loanlight.avm_efolder.retrying_unpublished_count`, grouped by bounded `reason`, stays ≥ 1 for a full 15-minute window. A missing or invalid Encompass loan ID follows the same repair path as CDA (see Encompass loan ID repair above). |
| `avm-efolder-expired-claim` | `loanlight.avm_efolder.expired_claim` warns at 1, alerts at 3 in 30 minutes. Counts leases that ran out with no retry code written. This is the duplicate-risk path — the producer cannot tell whether an expired claim published; event-level duplicate suppression is the integrations consumer’s `(report_kind, order_id)` ledger identity. |
| `avm-efolder-metrics-observation-failed` | Fires on `avm_efolder.metrics_observation_failed` with `reason: metrics_query_failed`. The backlog query failed; `oldest_eligible_unpublished_age_seconds`, `retrying_unpublished_count`, and `expired_claim` stop emitting (`on_missing_data: default` — those monitors go quiet). The sweep heartbeat is still emitted, so `avm-efolder-sweep-missing` stays green. Investigate database and query health; read durable state from the publication query instead of gauges. |
| `avm-efolder-publication-stuck` | Fires on `avm_efolder.publication_stuck` with `reason: eventbridge_rejected`. EventBridge returned a failed or ambiguous entry. Check the producer account, region, default bus, `PutEvents` permission, and that the consumer accepts `loanlight.avm.efolder.delivery.requested.v1`. The row retries on its own once the cause is fixed. |
| `avm-efolder-sweep-missing` | No publication heartbeat for 15 minutes. Staged reports for enabled lenders stop publishing. Check scheduler and task health, then the publication advisory lock holder. |

The acquisition and publication sweeps run every five minutes under their own Postgres advisory locks (`6203841597264833` and `6203841597264834` respectively). For operational details and read-only runbook SQL, see `packages/api/docs/avm-efolder-delivery-runbook.md` on `loanlight-api` `main`.

## Querying the producer outbox

```sql
-- Inspect a specific order's producer state.
SELECT id, lender_id, loan_id, status, pdf_s3_key, cda_efolder_eligible_at,
       cda_efolder_encompass_loan_id, cda_efolder_pdf_sha256,
       cda_efolder_event_published_at, cda_efolder_event_attempt_count,
       cda_efolder_event_next_attempt_at, cda_efolder_event_last_error_code
FROM collateral_review_orders
WHERE id = :order_id;

-- List eligible, unpublished rows for a lender (enabled backlog).
SELECT orders.id, orders.lender_id, orders.loan_id,
       orders.cda_efolder_eligible_at, orders.cda_efolder_event_published_at,
       orders.cda_efolder_event_next_attempt_at,
       orders.cda_efolder_event_last_error_code
FROM collateral_review_orders AS orders
JOIN lender_feature_flags AS flags
  ON flags.lender_id = orders.lender_id
 AND flags.feature_key = 'cda_efolder_delivery_enabled'
 AND flags.enabled = TRUE
WHERE orders.order_type = 'cda'
  AND orders.status = 'succeeded'
  AND orders.cda_efolder_eligible_at IS NOT NULL
  AND orders.cda_efolder_event_published_at IS NULL
ORDER BY COALESCE(
  orders.cda_efolder_event_next_attempt_at,
  orders.cda_efolder_eligible_at
), orders.id;
```

<Note>
A historical succeeded CDA row with `cda_efolder_eligible_at IS NULL` is deliberately inert — it predates the feature or was written while the flag was off. Do not backfill it into delivery.
</Note>
