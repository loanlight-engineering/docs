`frontend` (workspace package `frontend`, in `packages/frontend/`) is the live Encompass plug-in UI — the screen loan officers see inside Encompass when they run and review a LoanLight audit. It runs as an Encompass SSF (Smart Server Framework) embedded app via `@elliemae/em-ssf-guest`.

<Warning>
The legacy `packages/web-app/` frontend was **deleted** in commit `5b65c1b` (LOA-649, PR #365). `git ls-files packages/web-app` returns nothing; only stale build artifacts remain on disk. `frontend/` is the one and only live frontend. Any doc or system prompt that still references `web-app` as a frontend is stale.
</Warning>

## Stack

- Next.js **16.1.1**, React **19.2.3**, dev on **port 8000** (`next dev -p 8000`).
- Tailwind v4, Storybook 9.
- Deployed as a **static export to S3 + CloudFront** (build → `dist`; the `infra/` CDK uploads it). It is a pure client — there are no Next API routes (`route.ts`).
- State via `zustand` (`store/useEllimae.ts`, `store/useAudit.ts`).
- Datadog browser RUM/logs + PostHog for analytics, `pdfjs-dist` for in-app PDF viewing, Playwright for E2E.
- Consumes `@loanlight-engineering/shared-types` (`^1.13.0`) and `@loanlight-engineering/shared-ui` (`^0.8.0`).

## Routes

Under `app/`:

| Route | Purpose |
|---|---|
| `/` | Home — routes to `NewAudit` / `AuditRunning` / `AuditError`, or redirects to `/audit/embed/` on `Complete`, based on `originResponse.auditDetail.auditState`. |
| `/audit/embed/` | Audit results — mints a one-shot exchange token via `GET /integrations/audits/:auditId/external-url?embedContext=iframe&layout=full`, then renders the full portal audit view inside a sandboxed `<iframe>`. Falls back to an `AgentNotRunCard` if minting fails, with a **Retry** button. See [Audit results embed](#audit-results-embed-loa-285629513019-3071). |
| `/design-system` | Component gallery (non-prod). |

## The two backends it talks to

The frontend calls **both** backends directly.

<Tabs>
<Tab title="encompass service">
Via `encompass.service.ts` / `epc-api-service.ts`. Bootstraps with `POST /integrations/origin`, then polls or streams `GET /integrations/audit-details/:id[/stream]` (`audit-progress.service.ts` handles the SSE), lists and streams the result PDF via `/integrations/documents/...` (`document.service.ts`), and opens the rich pop-out results view via `/integrations/audits/:auditId/external-url` (`external-results.service.ts`). See the [HTTP API](/integrations/http-api).
</Tab>
<Tab title="loanlight-api directly">
Via `audit-api.service.ts`, against `NEXT_PUBLIC_LL_WEB_AUS_API_HOST`. It calls `GET /api/v1/audit_runs/{id}/results?includeNonIssues=true`, `/property_data`, `/urla_completeness`, `getCreditData` → `GET /api/v1/audit_runs/{id}/credit`, and `POST /bug-reports`. Requests send `X-Requestor-ID` plus a bearer token.
</Tab>
</Tabs>

## Audit results embed (LOA-2856/2951/3019/3071)

On a completed audit, the plug-in redirects to `/audit/embed/`. That page mints a one-shot exchange token via `GET /integrations/audits/:auditId/external-url?embedContext=iframe&layout=full`, then renders the full portal audit view — sidebar, all sections, key-field review — inside a sandboxed `<iframe>` (`AuditResultsFrame`). This is the **only** audit-results path: the previous per-section pages (`/audit`, `/audit/credit-liabilities`, `/audit/document-health`, etc.) and the `MergedAuditSidebar` component were **removed in LOA-3071**. Those pages duplicated the portal's unified per-section components; the shared components are now the single source of truth.

The portal mints the exchange URL when `embedContext=iframe`. Adding `layout=full` to the token payload unlocks the full sidebar layout and all audit sections inside the iframe. The `HostBridgeProvider` accepts `postMessage` calls only from the origin in `ENCOMPASS_HOST_ORIGIN` and applies Partitioned (CHIPS) cookies for cross-site embedding. `useEpcActionBridge` wires the iframe ref to the EPC action bridge so the host and the embedded portal can communicate.

Two environment variables govern the embed on the portal side:

| Env var | Effect |
|---|---|
| `ENCOMPASS_RESULTS_EMBED_ENABLED` | Must be `"true"` (strict) for `layout=full` token minting. Set in all environments. |
| `ENCOMPASS_HOST_ORIGIN` | Exact HTTPS origin the `HostBridgeProvider` `postMessage` handler accepts. |

Appraisal rental data, credit and liabilities, bank-statement income, document health, properties check, and all other audit sections are rendered by the portal inside the iframe. Entitlement gating (e.g. whether the bank-statements section appears) is enforced server-side — the plug-in no longer makes per-section entitlement checks.

<Note>
The appraisal review PDF is filed into the Encompass eFolder on every completed audit regardless of the lender's `document_push` flag (LOA-1993). For `document_push`-enabled lenders it routes to the `appraisal_review_summary` container. For non-routed lenders it travels as a bare "AUS Results" resource alongside the AUS report and property PDFs. The EPC inline audit surface should always find the appraisal PDF present on a complete audit.
</Note>

## Component conventions

From the package `CLAUDE.md`:

- Catalyst components live in `components/ui`.
- Route-local code is co-located: `_components/` (JSX) + `_helpers/` (pure functions).
- Every new component needs a Storybook story plus a gallery entry.
- Design tokens only — the Figma → Tailwind mapping is `accent` → `brand` and `grays` → `zinc`.
- SVGs are imported through the `assets/svg/index.ts` barrel.

For the audit data shapes the frontend renders, see [Audit lifecycle](/integrations/audit-lifecycle) and [Integrations database schema](/integrations/database-schema).
