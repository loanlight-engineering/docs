The integrations service exposes a secured admin API for managing per-lender feature flags — the same `lender_feature` table rows that gate document push, appraisal pass-through XML, and appraisal package delivery on the EPC path. It is served by `FeatureFlagAdminController` and mirrors the pattern established by the [routing-config admin API](/integrations/routing-config-admin) (LOA-1463).

The controller base path is `integrations/feature-flags`. There is **no global route prefix** — every path below is literal.

## Auth

Every route is guarded by `InternalApiKeyGuard` — the same guard used by the routing-config and document-push-outcomes endpoints.

- The caller sends the shared secret in the `x-internal-api-key` header. The guard reads `INTERNAL_API_KEY` (trimmed) and compares with `crypto.timingSafeEqual`.
- **Fail-closed**: an unset or blank `INTERNAL_API_KEY` returns `401` even with a matching header.
- The optional `x-acting-user-id` / `x-acting-user-email` headers are **logged only** — they appear in the `feature_flag_set` audit log line on every mutation; they are not part of authorization.

## Flag registry

The service maintains a code-defined registry (`feature-flags.registry.ts`) of the flags it manages. These are the per-lender `lender_feature` keys read by `resolveFeatureGate` in `aus-update.service.ts`, `webhooks.service.ts`, and `EpcClientRepository.getLenderFeature`; no new table or migration is required for new flags.

| `key` | Label | Default | Gates |
|---|---|---|---|
| `document_push` | Document Push | `false` | Routing of classified documents (bank statements, credit reports, etc.) into EPC eFolders |
| `appraisal_passthrough` | Appraisal Pass-Through XML | `false` | Manually-uploaded, non-MISMO appraisal XML alongside the appraisal PDF |
| `appraisal_package_delivery` | Appraisal Package Delivery | `false` | Partner-delivered appraisal packages (UAD 3.6 ZIP or UCDP SSR) |
| `aus_property_indexing` | AUS Property Indexing | `false` | Whether the AUS report, property report, and appraisal review-summary PDFs are routed via the `document_push_routing_config` table into specific eFolders. When `false` (default), these PDFs are delivered as bare "AUS Results" resources with no eFolder routing, regardless of the `document_push` flag. Added LOA-2466. |
| `ssr_only_detection` | SSR-Only Detection | `false` | Flag an audit run as SSR-only when every document new on that run landed in the lender's configured UCDP SSR eFolder. **Value-bearing** — requires the eFolder display name in `value`. Added LOA-2483. |
| `bucket_routing` | Bucket Routing | `false` | Enable the [bucket routing tier](/integrations/routing-config-admin#bucket-routing-tier-loa-2463) for this lender. When on, classify-failed documents with a known Phase 1 split bucket are routed by the global `bucketRules` config instead of collapsing into manual review. The tier runs before the classification lookup and preempts any lender-scoped `unknown` override for documents it covers. Leave off until bucket rules are seeded globally (LOA-2464) and the lender's destinations are confirmed. Added LOA-2554. |
| `findings_document_health` | Findings — Document Health | `false` | **Value-bearing** (`off` / `manual` / `auto`). Controls automatic delivery of Document Health audit findings as Encompass Conditions/Tasks via `CREATE_FINDINGS`. Only `auto` triggers delivery in the current release; `manual` is defined but inert. Added LOA-2039. |
| `findings_pii_validation` | Findings — PII Validation | `false` | **Value-bearing** (`off` / `manual` / `auto`). Same delivery mode semantics as `findings_document_health`. Added LOA-2039. |
| `findings_credit_evaluation` | Findings — Credit Evaluation | `false` | **Value-bearing** (`off` / `manual` / `auto`). Added LOA-2039. |
| `findings_property_data` | Findings — Property Data | `false` | **Value-bearing** (`off` / `manual` / `auto`). Added LOA-2039. |
| `findings_appraisal_evaluation` | Findings — Appraisal Evaluation | `false` | **Value-bearing** (`off` / `manual` / `auto`). Added LOA-2039. |
| `findings_urla_completeness` | Findings — URLA Completeness | `false` | **Value-bearing** (`off` / `manual` / `auto`). Added LOA-2039. |

The six `findings_*` flags share a common `FindingMode` type (`off` / `manual` / `auto`) parsed by `finding-mode.ts::parseFindingMode`. `enabled = true` with `feature_value = 'off'` reads as off at runtime. `enabled = false` or an absent row also reads as off.

All flags default to disabled (absence of a row = disabled). For **value-bearing flags** (`ssr_only_detection` and the `findings_*` family), `enabled = true` with a blank or absent value also reads as disabled at runtime — the stored `enabled` state is reported accurately by the admin API, but `resolveFeatureValue` returns `null` until a non-blank `value` is persisted.

<Note>
`document_push` and `aus_property_indexing` are **independent**. `document_push` controls whether classified documents are routed into eFolders; `aus_property_indexing` controls whether the AUS report / property PDFs are routed. A lender can have one without the other. Enable `aus_property_indexing` per-lender from the Octy EPC Feature Flags tab after verifying the legacy delivery path is no longer needed.
</Note>

## Endpoints

`:orgId` is a **WorkOS org id**. The service resolves it to a provisioned lender via `lender.workos_org_id`.

| Method & path | Action |
|---|---|
| `GET /integrations/feature-flags` | The code-defined flag registry (key, label, description, defaultEnabled, and for value-bearing flags: requiresValue, valueLabel, valueDescription). |
| `GET /integrations/feature-flags/lenders/:orgId` | A lender's effective flag values — all five flags merged with registry defaults (an absent row resolves to the default, never a 404). |
| `PUT /integrations/feature-flags/lenders/:orgId/:key` | Set one flag (upsert). Body: `{ "enabled": boolean, "value"?: string }`. Returns `{ key, enabled, value }` where `value` is `string \| null`. Audit-logged (see below). |

### PUT request body

For boolean flags:

```json
{ "enabled": true }
```

For value-bearing flags (`ssr_only_detection`), include `value`:

```json
{ "enabled": true, "value": "UCDP Submission Summary Report" }
```

- `@IsBoolean()` is enforced on `enabled`.
- `value` is optional (`string | null`, max 255 chars). Omitting it preserves the stored value. Sending a blank string returns `400 MISSING_FEATURE_FLAG_VALUE`.
- Enabling a value-bearing flag without a non-blank `value` (and none already stored) returns `400 MISSING_FEATURE_FLAG_VALUE`.
- Sending `value` for a non-value-bearing flag is silently dropped.

### GET lenders/:orgId response

```json
{
  "orgId": "<workos-org-id>",
  "flags": [
    { "key": "document_push", "enabled": false, "value": null },
    { "key": "appraisal_passthrough", "enabled": false, "value": null },
    { "key": "appraisal_package_delivery", "enabled": false, "value": null },
    { "key": "aus_property_indexing", "enabled": false, "value": null },
    { "key": "ssr_only_detection", "enabled": false, "value": null },
    { "key": "bucket_routing", "enabled": false, "value": null },
    { "key": "findings_document_health", "enabled": false, "value": null },
    { "key": "findings_pii_validation", "enabled": false, "value": null },
    { "key": "findings_credit_evaluation", "enabled": false, "value": null },
    { "key": "findings_property_data", "enabled": false, "value": null },
    { "key": "findings_appraisal_evaluation", "enabled": false, "value": null },
    { "key": "findings_urla_completeness", "enabled": false, "value": null }
  ]
}
```

All twelve flags are always present in the response.

## Audit logging

Every `PUT` performs a read-before-write and emits a structured log line:

```json
{
  "event": "feature_flag_set",
  "orgId": "<workos-org-id>",
  "key": "ssr_only_detection",
  "previousValue": false,
  "newValue": true,
  "previousFeatureValue": null,
  "newFeatureValue": "UCDP Submission Summary Report",
  "actorId": "<x-acting-user-id>",
  "actorEmail": "<x-acting-user-email>"
}
```

`previousValue` / `previousFeatureValue` are resolved server-side and stay internal to the log. This mirrors the `routing_config_authored` / `_activated` / `_deactivated` pattern in `RoutingConfigAdminController`.

## Error responses

| Status | Body | When |
|---|---|---|
| `409` | `{ code: "LENDER_NOT_PROVISIONED", message }` | `:orgId` does not resolve to a provisioned lender. |
| `400` | `{ code: "UNKNOWN_FEATURE_FLAG", message }` | `:key` is not in the registry. |
| `400` | `{ code: "MISSING_FEATURE_FLAG_VALUE", message }` | Enabling a value-bearing flag with no non-blank `value` (either sent blank or not sent and none stored). |

## Transport

This API is served on the integrations **internal NLB**, not the public gateway — the same NLB as the routing-config admin and document-push-outcomes endpoints. See [Integrations infrastructure](/integrations/infrastructure) for NLB and security group details.
